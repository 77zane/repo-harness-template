# 提交前核对与独立只读 Review 手册

在准备提交 PR 或完成高风险改动前按需加载执行。

## 1. 最后一次改动后跑完确定性门禁

在仓库根目录运行 `npm run check`，确认所有阻塞门禁全部通过。若在跑完后又改了任何文件，必须重新执行，严禁拿旧结果汇报通过。

若 `check:contract` 对某业务域输出了 `WARN` 提醒：
- 若改动影响了存储状态、输出载荷、参数校验或失败模式，在同一轮更新对应 `src/domains/<name>/contract.md`（涉及全局红线时同步更新 `docs/ARCHITECTURE.md`）；
- 若确属纯内部重构且契约未变，在交付说明里明确写出依据。

## 2. Bug 修复防复发三件套核对

每一次真实 Bug 修复，确认同一轮沉淀进三件活资产（不写只写不读的历史复盘）：
1. **活文档**：若暴露了缺失的契约或红线，已原地补进 `docs/ARCHITECTURE.md` 或对应域 `contract.md`；
2. **就近 `Why` 注释**：涉及反直觉数值上限、顺序约束或不变量时，已在源码正上方补 1 行原因注释；
3. **可证伪红灯门禁**：新增回归测试钉在能观测到该 Bug 的最高边界层（优先 `tests/boundary/`，而非孤立底层类），并已验证去掉修复时测试确实报红、恢复修复后转绿（若新增或改动了 `scripts/` 门禁或 Hook，同步在 `tests/architecture/` 补反例自测）。

## 3. 独立只读 Review（仅高风险改动触发）

当 diff 触及 `docs/ARCHITECTURE.md`、`contract.md`、`src/foundation/`、`src/app/`、`.agents/hooks.json`、`scripts/` 或并发/安全/解析逻辑时触发；普通小改直接跳过。

拉起**独立只读 Review 视角**（只读 subagent 或单独审 `git diff`），同时过两把尺子：

1. **业务契约视角**：
   - 是否违背了 `docs/ARCHITECTURE.md` 或所属 `contract.md` 中的红线？
   - 是否存在“局部看似变快、实则静默削弱用户体验”的破坏性优化？
2. **传统工程缺陷视角**：
   - 边界输入校验是否遗漏（`NaN`、负数、带单位字符串、空载荷）？
   - 是否存在资源泄漏（未清理定时器、监听器、子进程）或并发竞态？
   - 跨平台路径（Windows / POSIX）处理与测试断言是否存在假阳性？
   - 是否悄悄留下了无用兼容垫片、死分支或空 `catch`？

## 4. 如实汇报

只汇报本次实际运行过的命令、精确通过数，以及未在自动化门禁中覆盖的真环境验证范围。
